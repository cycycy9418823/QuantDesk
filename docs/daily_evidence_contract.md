# 每日研究资料：维护、留档与恢复使用同一清单

本协议服务于宪章§2、§3、§7、§8。只用于纸面研究，不接券商、不改变策略、费用、成交方式或账本计算。价格口径继续服从 `docs/price_data_contract.md`；未来复权信号加原始价格成交的双轨桥仍未实现。

## 每天分别完成什么

收盘原始日线和估值仍走既有全A快照路径，指数、新闻、财报继续各自维护。候选生成后，在同一 Data Close Pipeline、同一 OS 写入锁和能力租约内，增加一次有预算的因子证据维护。晚间复盘封存原始资料。原夜间备份同时收集这些资料的依赖。没有新计划任务。

| 事实 | 证明方式 | 不能因此推断 |
|---|---|---|
| 供应商响应成功 | 返回码、完整响应字节、实际接收时间 | 所需日期和字段已经齐全 |
| 当日行情覆盖 | 原始帧先验口径检查、目标日、价格字段和来源 | 旧研究窗口或因子完整 |
| 因子研究资料覆盖 | 明确日期窗口、原响应、来源类型与完整性检查 | 异源归一化、原生逐日记录或执行双轨已经实现 |
| 当日账本更新 | 账本业务日期 | 每笔历史交易都有原始证据 |
| 原件留档 | 账本前后字节、动作原件、价格/日历原件及带时区的实际捕获时间 | 旧的无时区时间已恢复，或复盘时间就是交易前预测时间 |
| 备份成功 | 复制的字节及引用依赖全部核对 | 复制的是当天账本，或者已经在新目录恢复过 |

状态展示同时给“研究资料”结果，列出行情、因子、账本日与动作原件缺项。缺项是标签，链继续运行；不能支持的研究结论保留未验证状态。当前日与登记的旧研究窗口分别计算。

## 共同要求与范围

`quantdesk.daily_evidence_contract` 从实际持仓、当天正式候选批次与显式登记的研究窗口建立同一份要求。持仓从原始 `entry_date` 开始，候选从当天开始。身份、日期、来源文件及要求的SHA都保留。日历必须含所需区间的明确交易日标志，不用工作日代替缺日历。

当天候选文件缺失是范围缺项，不能当成“没有候选”或空资料清单；因子维护会保留该原因，不发起不明范围的查询，也不报告维护完整。

历史窗口可在本地运行资料 `state/daily_evidence/requests.json` 登记，例如：

```json
{
  "schema": "daily_evidence_requests.v1",
  "windows": [{
    "request_id": "exit_comparison_20260917_20261030",
    "scope": "historical",
    "purpose": "strategy_comparison",
    "start_date": "2026-09-17",
    "end_date": "2026-10-30",
    "symbols": ["300017"],
    "factor_policy": "native_only"
  }]
}
```

它是运行资料，不进Git。新增/修改正式文件仍需要指定运行写手和许可；本包的审计CLI只读。未登记的其他历史不会被宣称完整。缺原始流水、退出关联或时区的旧记录不靠汇总重建。

## 因子来源与解释

维护范围最多100只实际需要的股票；每次维护最多32次请求、60秒，串行且请求间隔0.75秒。先复用覆盖所需窗口的已验证缓存或显式导入的原生每日因子，再对缺项查询新浪公开hfq事件序列。北交所等新浪不支持的范围会说明需本地原生来源，不能伪装响应成功。超时进程由现有截止时间执行器退出；未结束请求可能已在途，不能把它们记成“请求0次”。

固定端点查询不跟随HTTP重定向，避免一次任务扩成额外请求；重定向响应保留为失败来源证据，不进入可用因子索引。

新浪源验证：确切股票变量、固定端点、响应SHA/字节数、HTTP 200、完整响应声明、`total == len(data)`、严格日期顺序、不重复、正有限十进制、1900种子及上市起始事件。响应实际时间必须晚于所需完整收盘日。脚本只解析JSON，不执行供应商JavaScript。

扩展按每个事件生效日使用当时的最新事件，原始十进制文本保持。方法依据是已有 AKShare `stock_zh_a_daily` 的hfq处理：它读取同一hfq事件源，按日使用事件值，再乘原始价格。1900种子保留为来源资料，不当交易日，也不代替缺失的事件。验证的是供应商声明的完整事件列表和可观察窗口，**没有独立证明供应商无遗漏或数值无误**。

结果类型明确为 `derived_sina_hfq_events`、研究proxy、非原生每日行、未验证异源归一化。不拼接或改写旧 `data/metadata/adjustment_factors.csv`，不接入账本数量/成本的公司行动调整。要求 `native_only` 的原有研究消费者仍将它列为不满足；本包没有放宽P2的检查。

显式本地原生来源用 `native_daily_csv`，逐行包含 `trade_date,symbol,adj_factor,source`，保留完整原响应SHA和带时区观察时间。缺一天、混来源或混代码都不接受。导入描述放在 `data/metadata/adjustment_evidence/imports/<symbol>.json`，其中 `raw_source` 是已封存原响应的路径/SHA引用，`source_proof` 是对应来源、时间、字节数及类型。该文件同样是受运行写入授权约束的资料，不是新源码或新的自动外网通道。

## 原件留档与备份

晚间复盘在既有日期锁里捕获账本前后原件。动作字典原样保存；额外的证据、实际捕获区间和关联放在独立记录中。相同运行只封存一次，不改原时间。原始价格帧先做完整口径检查，再核当日原始收盘价。未实现其他成交模型的验证桥，不能把收盘价匹配冒充 `next_open` 验证。

新买入、加仓、部分退出和完整退出按原动作数量及前后持仓核对。只有前一原件账本指纹相符的链才接续；缺旧开仓事件的退出仍保留缺项。数量不能解释时，退出关联标未核验，不算完整退出。相同运行遇到不同原件是冲突，不覆盖。

原件已写入但查询指针发布中断时，相同运行重试会先核对原件和依赖，再续发缺失或仍指向较旧记录的指针。原始捕获时间不变；已发布的较新运行不被旧运行重试覆盖。

原件在 `results/strategy_evidence/`；因子来源在 `data/metadata/adjustment_evidence/`；每个阶段的要求与就绪回执在 `results/daily_evidence/<业务日期>/`。引用都带完整SHA，原件按内容寻址，后来的行情追加不会改变已封存版本。只有小查询指针更新。

封存包括当前要求、原动作及已登记历史窗口涉及的价格原件。当前成交校验只使用当前要求和实际动作的股票；仅用于旧研究窗口的缺文件或非raw口径由历史资料检查保留缺项，不把当前原始价格成交判定一并降级，也不把旧窗口伪装成完整交易证据。

既有 `paper_state_backup` 依赖收集自动携带这些指针、原件、因子响应与转换依据。原全A数据资产仍由P5项目恢复方案处理，不把整个 `data/daily` 作为松散证据依赖纳入小型纸面账备份。原来16MB单件、128MB总量和1000件的保护限额保留；超额或缺引用明确失败，不能丢掉资料后宣称完整。长期增长达到限额时由备份负责人处理保留范围，不自动删除原件。

备份结果有独立 `research_business_scope`：文件复制、账本业务日、当日复盘与原件绑定、研究资料可恢复分别说明。`isolated_restore_verified` 只有真的在全新外部目录写回并核对全部字节后才为真；没有正式恢复或覆盖现有目录的快捷路径。

研究可恢复状态只采用当天最新查询指针，要求同一运行的复盘回执、原件档案、资料要求和包内账本相互绑定。保留的旧成功记录不能覆盖后一次不完整结果。若本地备份原件已取得但内容指纹或依赖校验失败，健康行报备份失败，不能继续沿用旧复制成功记录。

## 只读检查

```powershell
python scripts/audit_daily_evidence.py --project-root E:/codex/quant_new --target-date 2026-10-30 --network false --json false
python scripts/audit_daily_evidence.py --project-root <恢复目录> --target-date 2026-10-30 --use-sealed-requirements --network false
```

检查不会联网、运行日更、调用模型、发送通知或写资料。恢复检查使用封存要求、价格和日历原件，不借用正式目录的文件来让结果变绿。收盘维护完成后的就绪状态仍可缺晚间账本与动作；晚间失败或仍是旧账时会留下当天的不完整回执。

本包交付候选不是正式安装或用户验收；安装和自然运行仍按Claude总装与所有者的固定范围确认执行。所有结果保持“纸面·未验证”。
