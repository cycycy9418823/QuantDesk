# 账务核验：金额和明细是否对得上

这一块只接收已经读入内存的账本，返回核验结果或新的金额投影。
它不读取行情、不决定买卖，也不保存、初始化或恢复账本。

| 遇到的问题 | 从哪里查 |
|---|---|
| 现金、持仓市值、总权益对不上 | `reconcile_paper_account` 的明细汇总和 `drift_fields` |
| 本金加盈亏与权益对不上 | `strategy_pnl_identity`；缺失、融资和冲突分别保留 |
| 原账缺现金、股数不是数字、列表格式错误 | `strategy_state_errors`；用于存储前及读取时的原账核验 |
| 历史格式进入金额投影后报错 | `_paper_state_shape_errors`；它与原账核验的兼容规则不同 |
| 加仓成本更正重复、损坏或无法对应旧记录 | `realized_corrections.py` 的证据核验；本模块消费其结果 |
| 文件丢失、损坏、可用备份或身份不符 | 返回上层 `ledger_read_contract.py` / `state_store.py`，不在这里修文件 |

调用关系：执行器、证据新鲜度检查、更正预览、账本读取契约 → 本模块。
本模块依赖公共数值/代码转换及更正证据；不反向加载执行器、读取契约或存储器。
更正预览调用本模块时保留函数内导入，避免初始化循环。

`reconcile_paper_account` 返回深拷贝，不修改输入。它会按原规则计算明细汇总、
保留历史差额和更正证据、标记金额漂移及状态别名冲突。此投影不是已保存账本，
也不能用它的重算结果遮盖读取前的原始证据。是否写账仍由执行层决定。

`number` 与公共 `safe_float`、原账核验与兼容投影校验各自保留，未合并语义。
分币舍入、错误码、缺失提示、融资未核验状态和历史差额规则沿用原实现。
旧执行器、旧读取契约的同名入口继续兼容；旧执行器写手的注入点和路径解析保持。
核验函数内部的测试替换应注入本目录；修改旧模块的内部辅助函数属性不会改变
迁出函数的全局依赖。现有业务与测试未依赖这种旧模块内部替换行为。

结构回归见 `tests/test_paper_accounting_boundary_20261105.py`。金额、更正、
T+1、部分退出、写失败恢复等行为仍由原有账务及成交测试覆盖。

本次只完成账务核验边界。执行协调、估值、锁、成交日志提交、发布顺序仍在各自
现有位置；下一批应围绕这些实际职责整理，不能把所有读写函数直接塞入存储器。
